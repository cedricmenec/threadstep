## Périmètre

- Déplacer uniquement les tâches ayant une preuve DELIVERED vers backlog/archive/ sans cocher leurs checklists historiques ; actualiser index et liens.
- Créer ou réutiliser une PR documentaire unique via GitHub App et CI check indépendante.
- Pour branches d'archive, adapter et tester séparément le garde de fusion native sans élargir la permission accordée aux agents de développement.
- Enregistrer archive_pending lorsque la PR reste ouverte ou échoue ; prendre en charge une réconciliation explicitement autorisée des livraisons manuelles.

## Critères d'acceptation et vérification

- [ ] Deux livraisons => une PR documentaire, zéro livraison => aucune PR.
- [ ] Après réussite de la première et échec de la seconde, seule la première peut être archivée.
- [ ] Archive pending ne rend jamais la tâche réexécutable, et les règles de main ne sont jamais contournées.
- [ ] Tests de non-régression et npm run check passent.

## Contrat d'exécution

- **Périmètre de fichiers envisagé :** scripts/asf/archive/ ; backlog/ ; tests/ ; docs/factory/ ; scripts/request-safe-auto-merge.mjs si justifié.
- **Hors périmètre :** Pas de fusion sans autorisation applicable, ni d'appel OpenRouter.
- Implémenter sur branche dédiée depuis main, avec une PR d'implémentation **indépendante** après livraison réelle des dépendances.
- Cette tâche concerne la factory. Le workflow OpenSpec actuel n'accepte que TS-NNN et refuse des chemins internes protégés. Utiliser une voie d'implémentation ASF spécifiquement autorisée, sans contourner les contrôles des agents produit.
- Dans la même PR, documenter les changements effectifs sous docs/factory/ et mettre à jour la checklist de cette tâche uniquement pour les tests réellement effectués. Exécuter `npm run check` et, si GitHub Actions est modifié, Actionlint et la vérification Bash.
- La création et la fusion documentaire de cette tâche **n'autorisent pas** l'exécution payante, la fusion de la PR d'implémentation, la modification de secrets ou de permissions.

## Revue post-PR (ne pas cocher avant exécution réelle)

Vérifier le diff, la CI indépendante `check` sur le bon SHA et l'absence de changement non autorisé. Fusionner seulement après autorisation et contrôles GitHub requis, puis vérifier `main` et Pages quand pertinents. Tracer limites et preuves ; aucune réussite ne doit être annoncée sur une simple intention.
