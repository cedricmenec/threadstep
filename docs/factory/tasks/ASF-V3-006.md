# ASF-V3-006 | Adaptateur Git Data GitHub à privilèges restreints, non déployé

Status: proposed implementation in draft PR; NOT deployed
Type: factory
Automation: manual
Priority: high
Dependencies: ASF-V3-003 (#70) and ASF-V3-005 (#73), both still under review

## Objectif

Préparer le **port Git Data HTTP réellement compatible avec GitHub REST** qui remplace l'implémentation mockée du stockage CAS V3, en gardant le réseau, les tokens et les workflows **hors de ce lot**. Réaliser des tests de contrat qui montrent les requêtes émises, les refus des entrées malveillantes et l'absence de retry après incertitude.

## Fichiers

- \`scripts/asf/v3/github-git-data-port.mjs\` : port Git REST durci, aucune API réseau ni token à l'intérieur ; appelle exclusivement un transport injecté. Fixe le dépôt à \`cedricmenec/threadstep\`.
- \`tests/asf-v3-git-data-port.test.mjs\` : simulateur HTTP compatible formes REST, préparation de deux commits frères et concurrence, refus des mauvaises formes et conflits, réponse perdue après mise à jour.
- \`docs/factory/v3-git-data-port.md\` : preuve de contrat, permissions minimales, limites et plan de qualification.
- La présente fiche de tâche.

## Contrôles d'acceptation

- [x] Le port \`getRef/getCommit/createTree/createCommit/updateRef\` est compatible avec le contrat proposé en #70.
- [x] La seule branche ciblable est \`refs/heads/asf/waves/<waveId>\`, avec \`waveId\` validé par expression stricte.
- [x] La seule entrée de tree modifiable est \`journal.json\`, mode \`100644\`, blob UTF-8 validé, schéma V3 minimal, taille bornée et absence de secrets détectables.
- [x] Le commit est à **un seul parent** et l'update-ref **sans force** ; aucune routine de retry implicite ni de réécriture de manifeste.
- [x] Aucune erreur de transport ne divulgue le message brut pouvant contenir un secret.
- [x] Tests préparés pour les APIs GET/POST/PATCH, le refus de paths arbitraires, la réponse perdue, une concurrente simulée et le cas 409/422.
- [ ] CI indépendante \`check\` réussie sur le SHA final de la PR, sans régression V1.
- [ ] Revue explicite de la politique d'initialisation de branche, de l'origine du manifeste, des permissions GitHub App et du traitement des conflits/erreurs.
- [ ] Qualification d'un vrai transport GitHub App **non payant** sur une branche isolée et avec un jeton limité, dans un lot séparément autorisé.

## Garde-fous et hors périmètre

La PR ne crée ni client HTTP connecté, ni token App, ni job payant, ni workflow GitHub Actions, ni journal de vague opérationnel. Elle n'accorde pas \`Contents:write\` à l'agent modèle ou au workflow courant.

L'API GitHub REST \`PATCH /git/refs\` avec \`force:false\` **n'a pas de paramètre \`expected_sha\`**. Le pseudo-CAS repose sur la création d'un commit dont le **seul parent** est le HEAD précédemment observé. Une mise à jour rapide d'un *commit frère* ne doit donc pas pouvoir fast-forwarder. Le contrat dépend des invariants de parenté et d'une protection effective de l'accès au ref. Le modèle ne protège **pas** de writers hostiles capables de créer une chaîne de commits valide.

Les tests sont **simulés** et ne prouvent pas que le port fonctionne avec un token App restreint ni que deux runners GitHub réels sont synchronisés. Aucun droit d'exécution payante n'en découle.
