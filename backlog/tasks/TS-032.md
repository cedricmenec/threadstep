# TS-032 | Utiliser IndexedDB par défaut sans compte Cloud

## User value
L'utilisateur doit créer, modifier et retrouver ses sujets dans IndexedDB dès le premier lancement, sans URL Dexie Cloud, OTP ou connexion réseau.

## Scope
- Initialiser un espace Dexie local autonome et versionné quand aucune configuration Cloud n'existe, sans construire d'instance synchronisée.
- Faire lire et écrire toutes les actions métier et l'export JSON depuis IndexedDB quel que soit le statut Cloud ; une écriture locale n'est annoncée qu'après commit.
- Garantir une transition explicite, non destructive depuis le mode localStorage livré ; ne pas purger ou masquer la clé historique.

## Acceptance criteria
- [ ] Démarrage sans Cloud, création, édition, suppression et rechargement maintiennent les mêmes données dans IndexedDB, avec URL et OTP absents.
- [ ] Les tests couvrent hors ligne initial, reload, échec transactionnel, stockage indisponible et confidentialité sans appel réseau.
- [ ] La vue métier n'exige aucune identité Cloud ; les tests DOM/accessibilité automatisables et `npm run check` sont verts.

## Implementation constraints
- Ne pas attacher les enregistrements locaux à une instance Dexie Cloud avant le consentement TS-037.
- Préserver la compatibilité des exports V1 et toutes les données existantes ; planifier la conversion historique via TS-033.
- Configurer les stores et identifiants compatibles Dexie Cloud sans activer d'envoi sur le mode local.
- Réviser les spécifications canoniques historiques contradictoires pendant la PR d'implémentation via le changement OpenSpec, sans réécrire rétroactivement l'histoire et sans changer les fichiers protégés ASF.
- Utiliser les exigences cibles `openspec/specs/local-indexeddb-persistence/spec.md` et les capacités liées (`threadstep-integration-profile`).
- Checklist OpenSpec `apply` uniquement pour changements et tests prouvables sur le runner, jamais recettes humaines ou tâches post-sync.

## Manual acceptance
Sur Chrome mobile, sans URL Cloud et hors ligne, créer des sujets et étapes puis recharger. Vérifier qu'aucun OTP n'est demandé et que les anciennes données restent exportables. À réaliser hors du runner ; ne pas cocher dans `apply`.

## Post-sync review
Comparer la synchronisation OPSX aux spécifications cibles, contrôler l'archive, la CI indépendante sur le SHA de PR, le merge, la CI de `main` et Pages. Ces contrôles restent distincts de la recette humaine.

## Out of scope
Activation/OTP Cloud, migration V1 complète, réconciliation avec une destination distante.

## Assumptions or decisions
Architecture local-first et Cloud facultatif approuvée le 18/10/2026. La conception technique reste à détailler en plan OpenSpec ; ne jamais exposer de données historiques avant opt-in. Aucune exécution payante autorisée par ce brief.
