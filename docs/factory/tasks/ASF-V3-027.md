# ASF-V3-027 — Protocole de qualification du mutex V1/V3

## Objectif

Préparer une qualification comportementale GitHub Actions du mutex `threadstep-paid-development-v1` **sans appel de modèle** et **sans perturber le dépôt de production**. Compléter la vérification **statique** de [#112](https://github.com/cedricmenec/threadstep/pull/112) par un protocole de collecte de preuves réelles ultérieur ; ne pas annoncer à tort une qualification live.

## Périmètre de cette PR

- [x] Spécifier les invariants de concurrence et de non-autorisation à payer.
- [x] Définir une matrice d'essais M01–M07 et les verdicts `pass` / `fail` / `inconclusive`.
- [x] Imposer un dépôt GitHub **isolé**, et proscrire tout harness partageant le mutex dans le vrai dépôt `threadstep`.
- [x] Définir les preuves REST à collecter, l'escalade des états ambigus et le refus de retry automatique.
- [x] Isoler la discussion `queue: max` dans une décision ultérieure, sans changement implicite de politique V1.
- [ ] Revue humaine du protocole, CI documentaire et acceptation du périmètre.
- [ ] Préparer dans un lot distinct le harness sans secret ; **aucun harness GitHub ni workflow de production ne sont ajoutés ici**.
- [ ] Autorisation propriétaire du dépôt laboratoire, puis exécutions réelles et rapport d'évidence.
- [ ] Revue et autorisation distinctes avant branchement V3 privilégié et premier paiement.

## Hors périmètre

Pas de changement de `.github/workflows/`, de code payant, de job V3 réel, de mutex V1, de token/secret, de `main`, de ref global, de ruleset, de bootstrap, de dispatch, d'ACK/CLAIM live ni d'OpenRouter. Pas de fusion par l'assistant.
