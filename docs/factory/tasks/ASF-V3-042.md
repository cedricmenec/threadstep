## Nouveau préflight

\`scripts/asf/v3/g2-lab-readonly-eligibility.mjs\` interroge uniquement les métadonnées et la collection paginée des rulesets d'un dépôt du propriétaire distinct de \`threadstep\`. La connexion REST est bloquée sur une allowlist de GET et ne peut ni déclencher un workflow, ni créer une ref, ni modifier des rulesets ou des permissions.

Un retour \`candidate_only\` signifie strictement **API rulesets lisible et collection exhaustivement parcourue**. Ce n'est jamais une approbation de l'utilisation du dépôt, de l'installation des Apps ou d'une mutation. Un 403 est \`blocked\` quel que soit le motif exact (plan/scopes) et ne peut être interprété comme une preuve de refus de writer par ruleset. 401/404, mauvais dépôt, dépôt archivé, pagination incertaine et données invalides échouent en mode fermé. Tous les flags d'autorité sont \`false\`.

Commande facultative, lecture seule, sans jeton nécessaire pour un dépôt public :

\`\`\`sh
node scripts/asf/v3/g2-lab-readonly-eligibility.mjs cedricmenec/asf-v3-ruleset-lab
\`\`\`

Un \`GH_TOKEN\` facultatif peut donner accès aux seules lectures si la connexion GitHub le permet. **Ne jamais l'inclure dans une commande, un commit ou des logs**. Aucune clé Controller/Executor ou App PEM n'est nécessaire à ce préflight.

Tests : \`tests/asf-v3-g2-lab-readonly-eligibility.test.mjs\` valide en transport fictif 403, public 200, absence de rulesets, pagination 100+, identité divergente, archivage, doublons, refus de chemins API et non-divulgation des secrets.

## Première intervention propriétaire incontournable pour le LIVE

Le connecteur actuel ne sait pas créer un dépôt GitHub dédié, modifier ses rulesets ni gérer les installations/tokens des deux Apps ASF. Pour une future campagne G3, il faudra :

1. **Fournir un dépôt dédié éligible**, de préférence un nouveau dépôt **public sans données sensibles** tel que \`cedricmenec/asf-v3-ruleset-lab\`, ou approuver explicitement un autre périmètre isolé compatible. Ne pas changer la visibilité de l'ancien labo ni réutiliser asf-agent-kits.
2. **Autoriser distinctement** la configuration des deux Apps Controller et Executor sur ce seul dépôt avec des droits minimaux, la pose des quatre règles de test et les futures mutations sur **refs de laboratoire uniquement**.
3. Vérifier et approuver les conditions de facturation des runners avant toute campagne GitHub Actions ; ne pas supposer que « sans LLM » signifie automatiquement « gratuit ».

Les tests purement simulés et les contrôles GitHub en lecture seule peuvent continuer avant cette décision. Le ref protégé opérationnel V3 de threadstep, G4 et toute dépense restent hors périmètre.
