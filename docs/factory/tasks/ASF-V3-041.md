# ASF-V3-041 : rulesets GitHub, refuser une collection non exhaustive

Statut : implémentation sur la PR canonique brouillon #183, non fusionnée.
Automation: manual. Risque: low (observateurs purs, aucun workflow/secret/ref).

## Constat du 23 octobre 2026

L'endpoint REST GitHub `GET /repos/cedricmenec/threadstep/rulesets` retourne par défaut une page de **30** résultats. Les observateurs G1 de la pile V3 inspectaient la collection sans lire de page suivante, avec un seuil de 64. Une première page complète aurait ainsi pu masquer un ruleset supplémentaire et produire à tort un constat de structure exhaustive.

## Correction

- Refuser, avant toute lecture détaillée, une collection contenant **30 éléments ou plus**. Une collection de 30 est ambiguë même si elle pourrait être complète.
- Émettre des motifs explicites `rulesets_pagination_unconfirmed` et `wave_ruleset_pagination_unconfirmed` ; conserver tous les flags d'autorisation à `false`.
- Conserver les cinq rulesets actuels inchangés et les scripts CLI en lecture seule.
- Tester avec 30 éléments synthétiques (arrêt sans seconde requête), puis 29 éléments (chemin de lecture des détails inchangé).

Ce correctif est volontairement conservateur : il n'ajoute pas un client paginé ni un droit de création. Un futur lot pourra introduire une collecte exhaustive avec vérification de toutes les pages et des en-têtes Link avant de relever cette limite.
