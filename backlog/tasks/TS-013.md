# TS-013 | Afficher le nombre de sous-tâches sur le bouton de repli

## Valeur utilisateur

Quand les sous-tâches d'une action sont masquées, je veux savoir combien
je peux en afficher, par exemple **« Voir 2 sous-tâches »**. Lorsque les
sous-tâches sont affichées, le bouton devient
**« Masquer les sous-tâches »**.

## Périmètre fonctionnel

- Modifier **uniquement le libellé du bouton de TS-012** (« Déplier » /
  « Replier »), sans créer de second contrôle.
  - Liste repliée avec un enfant visible : « Voir 1 sous-tâche ».
  - Liste repliée avec N enfants visibles (N > 1) : « Voir N sous-tâches ».
  - Liste dépliée : « Masquer les sous-tâches ».
- Compter les enfants directs visibles *selon le filtre courant*
  « Masquer les étapes terminées », **sans dépendre de leur repli**.
  Exemple : trois enfants dont un terminé produisent 3 sans filtre,
  et 2 lorsque le filtre masque les étapes terminées.
- Ne pas afficher de bouton lorsqu'aucune sous-tâche n'est visible,
  ni sur une sous-tâche elle-même. Réactualiser le décompte après
  ajout, retrait, restauration, complétion ou filtrage d'un enfant.
- Préserver TS-012 : sous-tâches initialement dépliées, repli indépendant
  par parent, état transitoire (réinitialisé après rechargement, nouvel
  onglet ou import), enfants inchangés et dans le même ordre.
- Bouton natif accessible, nom incluant **le nouveau libellé et le titre
  du parent**, `aria-expanded` exact et `aria-controls` vers la liste
  lorsqu'elle existe, focus cohérent, souris/tactile/Tab/Entrée/Espace,
  surface tactile d'au moins 44 × 44 px.
- Le clic ne sauvegarde rien : aucune mutation de `subject.items`,
  aucun stockage ajouté, aucun changement de compteur global, priorité,
  complétion, suivi, suggestion, ordre, identifiant ou export JSON.

## Critères d'acceptation

- [ ] Avec deux enfants visibles et repliés, le texte est exactement
      « Voir 2 sous-tâches » ; un clic montre les enfants et
      « Masquer les sous-tâches », puis un second les replie.
- [ ] Le singulier « Voir 1 sous-tâche » est exact ; aucun enfant
      visible signifie aucun bouton ; une sous-tâche n'a pas de toggle.
- [ ] Pour trois enfants dont un terminé, le nombre passe de 3 à 2
      avec le filtre ; déplier ne révèle pas l'enfant filtré.
- [ ] Un ajout, retrait ou une restauration d'enfant recalcule le texte
      au rendu suivant, sans affecter le repli d'autres parents.
- [ ] Le nom accessible inclut le titre de l'action, `aria-expanded`
      et `aria-controls` sont corrects, le clavier et le focus
      fonctionnent comme avant.
- [ ] Cliquer sur le bouton ne change jamais les données exportées,
      le stockage local, la priorité ni les compteurs métiers.
- [ ] Ajouter des tests Node déterministes : 0 / 1 / plusieurs enfants,
      filtre et non-mutation ; `npm run check` est vert. Mettre à jour
      le guide et les specs OpenSpec.

## Contraintes d'implémentation

- Périmètre réduit au bouton de TS-012 dans `site/app.js`,
  avec éventuellement une fonction pure de formatage dans `site/core.js`,
  des tests, styles et documentation produit. Garder la version du
  document `threadstep.document.v1` et la compatibilité mobile.
- **Indépendante de TS-014** : ne pas toucher aux poignées de
  glisser-déposer, au déplacement d'enfants ni aux événements pointeur.
  Le libellé fonctionne dans n'importe quel ordre d'enfants.
- Application statique ; pas de dépendance, réseau, nouvelle clé de
  stockage, secret, modification GitHub Actions ou de la factory.

## Hors périmètre

Réordonner des sous-tâches, changer leur état, les supprimer au repli,
replier par défaut, enregistrer un compteur, créer plusieurs niveaux,
ajouter un bouton « Tout replier ».

## Décisions, dépendances et risque

- Le bouton et la structure à un niveau de TS-012 sont déjà livrés
  dans `main` par [PR #55](https://github.com/cedricmenec/threadstep/pull/55).
  **Aucune tâche future en dépendance** (`depends_on: []`).
- **Risque faible identifié** : texte et présentation seulement, sans
  changement de structure, mutation de données ou permission, avec
  validation par tests. Task `product/ready/allowed/low` pour le
  second pilote ASF ; éligibilité ≠ autorisation de dépense ou de fusion.
- Revue post-livraison (hors cases OpenSpec) : vérifier le comportement
  au clavier et sur mobile, les textes pluriel/singulier et la CI/Pages.
