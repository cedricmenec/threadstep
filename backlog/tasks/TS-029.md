# TS-029 | Séparer changement de base, déconnexion et purge locale

## Valeur utilisateur

Passer d'une instance à l'autre, quitter la session et purger seulement la base sélectionnée sans effacer le serveur.

## Périmètre fonctionnel

- Changement explicite d'URL : stocker nouvelle URL locale, fermer le contexte Dexie et réinitialiser/recharger si nécessaire. nameSuffix reste actif, une autre URL correspond à une IndexedDB distincte sans copie/migration.
- A/B/A réutilise la base A intacte. Si B est inaccessible ou refuse l'accès, revenir vers A sans suppression locale.
- Déconnexion par db.cloud.logout(), jamais purge applicative implicite de toutes les bases ; avertir du risque natif de perte de modifications non synchronisées, confirmation explicite et annulation.
- Action de purge locale distincte : afficher nom de la base, risque de changements non poussés, confirmer puis supprimer uniquement IndexedDB sélectionnée (API de suppression de DB), sans delete métier répliqué ni effacement serveur.
- Après purge, annoncer que seules les données réellement synchronisées côté Dexie Cloud pourront être récupérées.

## Critères d'acceptation produit

- Retour A après B retrouve données et session encore valides ; B inaccessible ne détruit pas A.
- Déconnexion utilise API native avec avertissement/confirmation si pending, aucune purge d'autres DB commandée.
- Purge efface uniquement la copie locale ciblée, aucun delete distant ni suppression de la base Cloud.
- Annulation sans mutation et réauthentification après purge conforme aux seules données déjà répliquées.

## Actions d'implémentation vérifiables avant finalisation

- [ ] Construire changement d'URL, fermeture contextes, logout prudent, purge ciblée.
- [ ] Tester A/B/A, URL inaccessible, pending, refus de purge, suppression locale vs distante sur environnements isolés.
- [ ] Exécuter npm run check et openspec validate ts-029 --strict --no-interactive.

## Recette manuelle (hors checklist d'implémentation)

Recette réelle avec deux instances Cloud de test, déconnexion offline, purge et nouvelle authentification.

## Risques, dépendances, décisions et exclusions

- Risque **high**, `status: proposed`, `automation: manual` : pas de sélection automatique ni autorisation de coût/fusion implicite.
- Dépendances : TS-026, TS-028.
- Décision : Le comportement natif Dexie de logout peut affecter des données locales : ne jamais le présenter comme une conservation garantie.
- Hors périmètre : Purge globale, effacement distant, export automatique entre deux URL, restauration du non synchronisé.
- Norme : [spec Dexie Cloud](../../docs/product/specs/dexie-cloud-local-first.md) et [plan de livraison](../../docs/product/dexie-cloud-rollout.md).
