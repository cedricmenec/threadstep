# TS-035 | Rendre les imports et restaurations JSON réellement idempotents

## User value
Importer deux fois le même export ou restaurer un ancien fichier ne doit jamais créer de doublons ou masquer des changements plus récents.

## Scope
- Valider et versionner les exports/imports avec conservation des identifiants métier, de leur provenance et des relations.
- Supprimer les préfixages récursifs `legacy:legacy:...` et reconnaître les exports issus de la base Dexie déjà migrée.
- Séparer les opérations UI « importer et fusionner » et « restaurer », avec comparaison, portée, confirmation et sauvegarde préalable pour toute action potentiellement destructive.

## Acceptance criteria
- [ ] Deux imports du même JSON historique, local ou Cloud ne produisent ni copie ni doublon supplémentaires.
- [ ] Un JSON exporté depuis un enregistrement `legacy:abc` réimporté garde son identité, et les parents/enfants restent cohérents.
- [ ] Import invalide, sauvegarde ancienne divergente, annulation, reload et échec de transaction préservent la cible et l'export ; `npm run check` passe.

## Implementation constraints
- Aucune restauration destructive automatique ; les effets vers Cloud exigent la réconciliation et le consentement distincts.
- Ne pas confondre backup applicatif V1 et sauvegarde administrative Dexie Cloud.
- Réviser les spécifications canoniques historiques contradictoires pendant la PR d'implémentation via le changement OpenSpec, sans réécrire rétroactivement l'histoire et sans changer les fichiers protégés ASF.
- Utiliser les exigences cibles `openspec/specs/data-backup-import-restore/spec.md` et les capacités liées (`legacy-storage-migration`, `threadstep-integration-profile`).
- Checklist OpenSpec `apply` uniquement pour changements et tests prouvables sur le runner, jamais recettes humaines ou tâches post-sync.

## Manual acceptance
Sur Chrome mobile, exporter, importer deux fois, vérifier les IDs/relations et tester la prévisualisation d'une ancienne sauvegarde sans écraser la base. À réaliser hors du runner ; ne pas cocher dans `apply`.

## Post-sync review
Comparer la synchronisation OPSX aux spécifications cibles, contrôler l'archive, la CI indépendante sur le SHA de PR, le merge, la CI de `main` et Pages. Ces contrôles restent distincts de la recette humaine.

## Out of scope
Un nouvel outil administratif de sauvegarde Dexie Cloud, sauvegardes serveurs, suppression automatique de versions.

## Assumptions or decisions
Architecture local-first et Cloud facultatif approuvée le 18/10/2026. La conception technique reste à détailler en plan OpenSpec ; ne jamais exposer de données historiques avant opt-in. Aucune exécution payante autorisée par ce brief.
