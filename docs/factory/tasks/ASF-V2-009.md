## Livraison d'intégration ASF-V2-009 (en PR, non activée avant fusion)

Le workflow `.github/workflows/backlog-orchestrator.yml` est **owner-only**, sur `main`, `workflow_dispatch`. Le mode `execute` autorise directement une vague bornée ; `dry-run` ne crée aucune branche, réservation durable ou appel modèle. Les paramètres sont limités à `max_tasks=1..2`, modèles allowlist et politique de fusion choisie. Un rerun du même GitHub run est refusé.

L'orchestrateur utilise **deux jobs `workflow_call` statiques maximum** (premier, second), avec un job de vérification de livraison entre les deux. Un échec ou résultat incertain n'autorise aucune substitution, même si le quota théorique n'est pas atteint.

Le manifeste fige `candidateTasks`, leurs SHA-256 exacts, le SHA GitHub source et le parent propriétaire. Le journal est persisté sur `refs/heads/asf/waves/<wave_id>` avant appel OpenSpec ; toute mise à jour de journal vérifie la valeur précédente de branche par lease Git. Le précontrôle de 008 exige la réservation exacte.

Chaque vérification de livraison exige PR finale de bot sur la branche attendue, contrôle `check` de PR et de main, fusion effective sur main et CI/Pages après fusion. Un run OpenSpec conclu ne suffit pas. Le timeout et les états GitHub inconnus bloquent la suite.

Le parent ne détient **jamais** le verrou de développement payant acquis par les jobs d'agent. Les changements intégratifs à `agent-openspec.yml` garantissent que la deuxième tâche parte de la dernière version de `main` tout en vérifiant que son brief reste inchangé.

**Limites :** pas de plafonnement USD fournisseur, pas de troisième tentative, pas de retry automatique, aucun archivage documentaire dans cette tâche (ASF-V2-010). La publication de cette PR est une modification de workflow sensible et ne constitue pas une autorisation de lancer une vague payante. La première recette réelle relève d'ASF-V2-011.
