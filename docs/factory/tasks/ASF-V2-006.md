## Critères d'acceptation et vérification

- [x] Trois départs sont impossibles quand max_tasks=2, y compris en cas de reprise. Vérifié par `tests/asf-waves-journal.test.mjs` : après deux réservations `DISPATCH_RESERVED`, `planDispatch` renvoie `QUOTA_REACHED` et `beginDispatch` renvoie `quota_reached` sans muter le journal ; après sérialisation + `reconstructJournal` (et via `commitEvent`/`loadJournal` du store durable), `taskStartsReserved` reste à `2` et le troisième départ reste refusé.
- [x] Issue de dispatch incertaine => STOP_UNCERTAIN, jamais second dispatch automatique. Vérifié : un événement `DISPATCH_UNCERTAIN` comme un `DISPATCH_RESERVED` non confirmé (crash pendant dispatch) produisent `STOP_UNCERTAIN` pour toute la vague (`planDispatch` sur une autre clé inclus) ; tout nouvel événement est refusé (`wave_stopped`) et un second `RESERVE_DISPATCH` sur la même clé reste bloqué, y compris après reconstruction.
- [x] Le journal reconstitué garde les décisions, SHA et liens sans secrets ; tests sans paiement réussissent. Vérifié : `summarizeJournal` d'un journal reconstitué conserve l'historique d'états, `headSha`, `mergeCommit`, URLs/numéros de run et de PR, et `isSecretFree` reste vrai ; un payload portant un jeton est refusé (`secret_detected`) sans être persisté ; test statique interdisant réseau, I/O, `child_process`, `fetch`, `Math.random` et `new Date` dans `scripts/asf/waves/` ; `node --test tests/asf-waves-manifest.test.mjs` → 9 réussis, `node --test tests/asf-waves-journal.test.mjs` → 18 réussis, `npm run check` → 210 réussis, `backlog:check` (11 actifs, 0 archivé), `node --check site/core.js` et `node --check site/app.js` (aucun workflow modifié, donc Actionlint non requis).
