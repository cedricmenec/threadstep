# TS-004 | Réordonner les sujets

Status: implemented; PR #4 merged
Priority: normal
Dependencies: TS-001
Source: product conversation, 2026-10-14

## User value
As someone switching between parallel work streams, I want to reorder my subjects quickly so that the most important subject is at the top when I return to ThreadStep.

## Scope
- Add clearly identifiable move-up and move-down controls to each subject card.
- A move swaps that subject with the previous or following subject in the displayed subject order. Do not sort subjects automatically by their action priorities.
- Disable or omit the unavailable direction at the top and bottom of the list.
- Persist the new subject order using the existing `threadstep.document.v1` localStorage document shape and normal save path.
- Keep subjects, their actions, substeps, completion status and priorities intact. Do not alter the JSON export/import format.
- Controls must work by touch and keyboard, with accessible French labels identifying both action and subject.
- Keep existing responsive mobile layout and product styling.

## Acceptance criteria
- [ ] With three subjects A, B, C, move C up once: the visible order becomes A, C, B.
- [ ] Moving A up or C down at the boundary is impossible and does not modify data.
- [ ] A page reload retains the reordered subjects in the same browser.
- [ ] Export and reimport of the reordered data preserve subject order and every action.
- [ ] Reordering an existing subject never alters its actions, priorities, completion flags or substeps.
- [ ] Controls are keyboard accessible, touch-friendly, and have descriptive accessible labels.
- [ ] Pure ordering logic receives focused automated tests; `npm run check` succeeds.
- [ ] No backend, third-party dependency, schema version increment or storage-key change.

## Implementation guidance
Favor a small pure function in `site/core.js` for moving a subject by one position and UI wiring in `site/app.js`, with minimal `site/styles.css` updates. Handle DOM re-render and focus sensibly.

## Out of scope
Drag-and-drop, automatic subject ranking, multi-user features, remote synchronization, reorder of actions inside a subject, and autonomous merging of pull requests.

## Decisions
This is a development task, not a request to trigger OpenRouter. The execution workflow still requires an explicit `task_id` input.
