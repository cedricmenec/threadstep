# TS-007 | Mode « Une seule prochaine étape »

Status: implemented; OpenSpec PR #18 merged
Priority: normal
Dependencies: TS-001
Source: first controlled OpenSpec auto-mode test, 2026-10-14

## User value

When juggling many subjects, I want a one-tap « Sur quoi avancer maintenant ? » suggestion so I can start a concrete next action without browsing all lists.

## Scope

- Add a visible, accessible French « Une étape pour maintenant » control near the global unfinished counter.
- Clicking it displays a compact, non-modal focus card with exactly one eligible unfinished **top-level action**: its subject name, action title and priority. Include a « Voir dans la liste » control that scrolls to and focuses or highlights that action accessibly.
- Select deterministically from the current document: urgent before normal before later; for equal priority, earlier subject order then earlier underlying item order. Do not use randomness, dates, network requests or AI.
- A completed action is never eligible. Substeps are not independently eligible for this first version; a completed parent with unfinished children is not eligible.
- When no eligible top-level action exists, show a friendly French empty-state message instead of a broken card.
- The suggestion is view-only: no completion, edits, reorder or storage changes. Recompute from current state on each click; do not persist the focus card across reload.
- Use safe text nodes for user content and a keyboard-/touch-accessible control with a sensible focus destination.

## Acceptance criteria

- [ ] With urgent, normal and later unfinished top-level actions across subjects, the card shows the first urgent action in subject order.
- [ ] Within the same priority, changing subject order changes the selection predictably; within one subject, original item order wins.
- [ ] Completed actions and all nested substeps are excluded; no eligible top-level action displays a clear empty state.
- [ ] « Voir dans la liste » brings the selected action into view with keyboard-accessible focus or a visible highlight, including on mobile.
- [ ] Repeated clicks are deterministic for unchanged state and reflect changes made to completion, priority or subject order.
- [ ] Clicking the control does not modify localStorage, exported JSON, IDs, done flags, priorities, item order or subject order.
- [ ] Unit tests cover the pure selection helper and empty-state cases; `npm run check` passes.
- [ ] Documentation task: update relevant `docs/product/` documentation for the new behavior and its limits; do not change `docs/factory/` or factory policies for this product-only feature.

## Implementation constraints

- Prefer a pure selector in `site/core.js` and small UI additions in `site/app.js` / `site/styles.css` or `site/index.html`.
- Keep the document schema, localStorage key, JSON import/export and GitHub Pages URLs unchanged.
- No new dependencies, external services, telemetry or backend.
- Do not modify workflows, `AGENTS.md`, OpenCode/OpenSpec configuration, secrets or protected factory files.

## Out of scope

- AI-generated suggestions, random rotation, timers, Pomodoro, notifications, due dates, substep recommendations, automatic completion and storing the last suggestion.

## Assumptions or decisions

- The feature is intentionally deterministic and small enough for one bounded OpenSpec auto run.
- Top-level actions only, regardless of nested substep status.
- Preparing this task does not authorize OpenRouter use. Run `phase=auto` only after the task PR and workflow PR #13 are merged and the owner explicitly launches the workflow.
