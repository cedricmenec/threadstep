# TS-033 | Convertir le document historique V1 vers la base locale

## User value
Les 5 sujets et 18 étapes d'un document `threadstep.document.v1` doivent pouvoir rejoindre IndexedDB sans fuite Cloud ni perte de contenu.

## Scope
- Détecter et valider strictement le JSON V1, puis prévisualiser la migration locale source → IndexedDB, avec consentement et conservation de la sauvegarde.
- Mapper sujets, étapes, sous-étapes, relations, ordre, notes, priorités, done et préférence locale ; ne pas préfixer récursivement les identifiants déjà convertis.
- Gérer une cible locale déjà peuplée, les collisions, interruptions et reprises sans doublon ni écrasement ; enregistrer une provenance stable.

## Acceptance criteria
- [ ] Un V1 valide de 5 sujets/18 étapes est retrouvé après reload ; source V1 et export de secours restent inchangés.
- [ ] Une conversion répétée, un V1 invalide, une cible partiellement peuplée et une panne en transaction produisent un résultat non destructif et idempotent.
- [ ] Aucune conversion purement locale ne construit une instance Cloud ni ne déclenche un push ; tests de non-régression et `npm run check` passent.

## Implementation constraints
- Ne pas supprimer le localStorage historique ni confondre conversion de support et activation Cloud.
- Préciser stratégie de conservation et empreinte de source ; toute mutation de la source rend le plan périmé.
- Réviser les spécifications canoniques historiques contradictoires pendant la PR d'implémentation via le changement OpenSpec, sans réécrire rétroactivement l'histoire et sans changer les fichiers protégés ASF.
- Utiliser les exigences cibles `openspec/specs/legacy-storage-migration/spec.md` et les capacités liées (`threadstep-integration-profile`).
- Checklist OpenSpec `apply` uniquement pour changements et tests prouvables sur le runner, jamais recettes humaines ou tâches post-sync.

## Manual acceptance
Chrome mobile : conserver un export, convertir les données réelles en local sans configurer Cloud, recharger et comparer visuellement sujets/sous-étapes. À réaliser hors du runner ; ne pas cocher dans `apply`.

## Post-sync review
Comparer la synchronisation OPSX aux spécifications cibles, contrôler l'archive, la CI indépendante sur le SHA de PR, le merge, la CI de `main` et Pages. Ces contrôles restent distincts de la recette humaine.

## Out of scope
Transfert Cloud, remplacement destructif de données, nouveau format métier incompatible.

## Assumptions or decisions
Architecture local-first et Cloud facultatif approuvée le 18/10/2026. La conception technique reste à détailler en plan OpenSpec ; ne jamais exposer de données historiques avant opt-in. Aucune exécution payante autorisée par ce brief.
