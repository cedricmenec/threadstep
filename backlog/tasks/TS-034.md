# TS-034 | Diagnostiquer et relancer la synchronisation Dexie Cloud

## User value
L'utilisateur doit comprendre pourquoi Dexie n'est pas connecté et pouvoir relancer une lecture distante sans importer prématurément ses données.

## Scope
- Exposer en lecture seule la session, la connexion, la phase native, le pull initial, la base configurée, les erreurs classées et le statut des écritures locales.
- Différencier connecting, disconnected, offline, error, pulling, pushing, in-sync, indeterminate, sans transformer automatiquement un état transitoire en erreur permanente.
- Ajouter une relance native et contrôlée du pull initial, surveiller les états via observables et garantir qu'un échec ne conclut jamais à une base distante vide.

## Acceptance criteria
- [ ] Les tests d'intégration injectés couvrent tous les statuts et phases natifs, la reprise, les changements de session/URL, les erreurs de lecture et le cas de migration bloquée.
- [ ] Aucun diagnostic ne divulgue OTP, token, notes, email ou secret ; les états local/pending/synced ne sont pas confondus.
- [ ] La UI mobile offre un message et une action de relance accessibles ; `npm run check` passe.

## Implementation constraints
- Valider la sémantique réelle de `db.cloud.sync`, `syncState`, `currentUser` et `persistedSyncState` dans la version Dexie emballée.
- Ne pas simuler `connected` ni forcer l'import ou la connexion ; n'ajouter aucun secret et aucune mutation produit à la relance.
- La preuve de première lecture distante requiert une recette Cloud réelle, pas seulement un stub.
- Réviser les spécifications canoniques historiques contradictoires pendant la PR d'implémentation via le changement OpenSpec, sans réécrire rétroactivement l'histoire et sans changer les fichiers protégés ASF.
- Utiliser les exigences cibles `openspec/specs/cloud-sync-lifecycle/spec.md` et les capacités liées (`workspace-identity-isolation`).
- Checklist OpenSpec `apply` uniquement pour changements et tests prouvables sur le runner, jamais recettes humaines ou tâches post-sync.

## Manual acceptance
Avec instance Cloud de test : tester Chrome mobile, OTP, connexion lente, coupure réseau, refus de droit, relance, affichage diagnostic et premier pull. À réaliser hors du runner ; ne pas cocher dans `apply`.

## Post-sync review
Comparer la synchronisation OPSX aux spécifications cibles, contrôler l'archive, la CI indépendante sur le SHA de PR, le merge, la CI de `main` et Pages. Ces contrôles restent distincts de la recette humaine.

## Out of scope
Moteur de réconciliation, import JSON, remplacement du protocole natif Dexie.

## Assumptions or decisions
Architecture local-first et Cloud facultatif approuvée le 18/10/2026. La conception technique reste à détailler en plan OpenSpec ; ne jamais exposer de données historiques avant opt-in. Aucune exécution payante autorisée par ce brief.
