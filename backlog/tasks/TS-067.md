# TS-067 | Harmoniser visuellement le shell de navigation avec Stitch

## User value
Donner à ThreadStep un accueil et une navigation plus cohérents avec les références Stitch, avec un shell lisible sur desktop, tablette et mobile, sans perdre la simplicité ni la continuité des usages existants.

## Scope
- Harmoniser le shell partagé autour d'Overview avec les références visuelles approuvées : desktop « Mes Projets - Vue d'ensemble » (identifiant local DESKTOP-1), menu mobile M02 « Navigation mobile ouverte » et planche responsive M32.
- Reprendre la disposition de navigation latérale persistante visible sur desktop dans DESKTOP-1 et la présenter comme un tiroir ouvert par le bouton Menu sur les largeurs compactes, selon M02. À 1280 px, les quatre destinations sont visibles dans la navigation latérale ; à 768 px et moins, le bouton Menu ouvre le tiroir.
- Harmoniser le conteneur d'Overview avec le shell et les proportions desktop de Stitch. TS-066 reste propriétaire du contenu Overview ; cette tâche n'en refond pas les cartes, données, tâches ou commandes.
- Réutiliser la coque React, les composants et tokens CSS locaux. Mettre à jour la spécification canonique `openspec/specs/app-navigation` et la décision d'architecture `docs/product/react-app-shell.md` pour décrire le shell responsive et la nouvelle disposition desktop.
- Préserver la frontière de propriété existante : le shell React reste séparé des surfaces métier et de leurs propriétaires actuels.

## Acceptance criteria
- [ ] À 1280 px, le shell présente une navigation latérale persistante et une zone Overview lisible, cohérentes avec DESKTOP-1, sans dupliquer les liens ou les commandes.
- [ ] À 768, 430, 390 et 320 px, la navigation reste accessible par le bouton Menu et un tiroir lisible, sans débordement horizontal ni perte de libellé.
- [ ] Les quatre destinations conservent exactement leurs noms, leur ordre, leurs fragments, le routage par hash, l'historique Précédent/Suivant et la fermeture du menu après navigation.
- [ ] L'état de route courant est perceptible et exposé sémantiquement ; le menu reste utilisable au clavier et au toucher, avec focus visible, cible tactile d'au moins 44 px, fermeture par Échap et restitution de focus cohérente.
- [ ] Les changements de shell ne réinitialisent ni le scroll, ni le focus, ni les brouillons et interactions valides d'Overview ou du détail projet ; ils ne remontent pas la racine React du détail.
- [ ] Les composants continuent de respecter les propriétaires DOM et contrôleurs canoniques. Aucune route, destination, donnée, persistance, préférence, dépendance, police distante, icône distante ou comportement métier nouveau n'est ajouté.
- [ ] Les valeurs existantes de tokens sémantiques restent inchangées. Le responsive utilise les tokens existants et une règle de rupture locale documentée si nécessaire, sans nouvelle couche d'architecture.
- [ ] La spécification `app-navigation` et la décision d'architecture `docs/product/react-app-shell.md` décrivent le shell desktop/mobile livré et ses frontières ; les tests automatisés couvrent la parité des destinations, les états responsive structurels, l'accessibilité et l'absence d'effet métier.
- [ ] `npm run check`, `npm run build` et `npm run verify:build` réussissent ; la CI indépendante est verte sur le SHA final.

## Implementation constraints
- Respecter `AGENTS.md`, les spécifications canoniques, la CSP et les propriétaires DOM. L'architecture du shell peut évoluer dans la portée de cette tâche, mais ne doit pas déplacer Overview, les paramètres, les formulaires Cloud, les imports/restaurations ou les données vers une nouvelle racine React.
- Réutiliser en priorité `site/app-shell/AppShell.jsx`, `AppHeader.jsx`, `AppNavigation.jsx`, `AppShellSurface.jsx`, `site/styles/tokens.css` et `site/ui/`.
- Garder la navigation comme présentation des destinations existantes. L'approbation Stitch concerne l'UI/UX ; les fonctions proposées dans les maquettes restent hors périmètre.
- `automation: manual` : cette fiche prête et sa fusion ne déclenchent pas OpenRouter ; un lancement doit être autorisé séparément par le propriétaire.

## Out of scope
- Recherche, archives, partage, échéances, pièces jointes, nouvelles destinations, nouvelles routes, nouveaux filtres ou nouveaux parcours métier.
- Refonte du contenu ou des composants métier d'Overview déjà traités par TS-066.
- Changement du modèle de données, de Dexie Cloud, de l'identité d'espace, de la sécurité, de la persistance, des exports/imports ou de la restauration.
- Migration d'Overview ou d'autres surfaces métier vers React ; introduction d'une nouvelle dépendance, d'un framework CSS ou d'une couche d'architecture générale.

## Assumptions or decisions
Le propriétaire a approuvé les maquettes Stitch comme références visuelles et UX, desktop et mobile. Il autorise explicitement l'évolution de la décision d'architecture et de la spécification de navigation si nécessaire pour adopter le shell desktop visible dans DESKTOP-1 et le tiroir mobile de M02, tout en conservant les quatre destinations contractuelles. Aucun arbitrage produit supplémentaire n'est requis pour cette portée.

## Manual acceptance
Après implémentation, vérifier le shell sur navigateur desktop et Chrome Android aux largeurs 320, 390, 430, 768 et 1280 px. Parcourir les quatre liens, le bouton Menu, le tiroir, les états clavier/tactile, Échap, le focus, le retour navigateur et la continuité de scroll et des brouillons. Documenter ce qui a réellement été vérifié ; cette recette n'est pas une condition préalable au lancement et n'est pas prouvée par jsdom ni par la CI.

## Post-sync review
Contrôler le diff sémantique, les mises à jour de spécification et de décision d'architecture, les tests OpenSpec, la CI indépendante sur le SHA exact, l'archivage OpenSpec, la CI sur main et Pages. Distinguer les preuves automatisées de toute recette humaine déclarée.
