# TS-005 | Modifier une étape existante

Status: implemented; OpenSpec PR #8 merged
Priority: normal
Dependencies: TS-001
Source: product conversation, 2026-10-14

## User value

As a ThreadStep user, I want to correct the title or priority of an existing
next action without deleting and recreating it, so that I can keep its completion
status, substeps and history in the same browser.

## Scope

- Add a visible, keyboard- and touch-accessible French **« Modifier »** control
  to each action, including one-level nested substeps.
- On activation, display a small inline editor (preferred for mobile) prefilled
  with the current action title and priority (urgent, normal, later).
- Provide clear **« Enregistrer »** and **« Annuler »** controls. Only confirmation
  changes the data; cancellation discards pending edits.
- Reject blank or whitespace-only titles and titles longer than 300 characters.
  Trim surrounding whitespace before saving. Do not corrupt the existing item
  when validation fails.
- After save, update the visible title and priority. Continue displaying actions
  in priority order **within their existing hierarchy level**, as today.
- Editing a parent action must not modify, lose or re-parent its substeps.
  Editing a substep must not change its parent.
- Preserve the existing action ID, `done`, `parentId`, subject, other action
  fields, and the document storage format. Only `title` and `priority` may
  change when the edit is saved.
- Reuse the existing automatic localStorage persistence and JSON export/import;
  stay compatible with existing documents and GitHub Pages deployment.
- Keep untrusted text rendered via safe text nodes, not injected HTML.

## Acceptance criteria

- [ ] An existing action shows an accessible « Modifier » button; activating it
      reveals its current title and priority in editable controls.
- [ ] Rename « Appeler Paul » to « Relancer Paul » and change its priority from
      normal to urgent; the list shows the updated title and priority.
- [ ] After priority change, the edited action follows existing priority sorting
      for its level; other actions and subject ordering are unchanged.
- [ ] « Annuler » closes editing without mutating the document or persisting
      draft values; the original title and priority remain.
- [ ] Empty/whitespace-only titles and titles exceeding 300 characters cannot
      be saved; the existing action remains intact and an understandable
      validation indication is provided.
- [ ] Rename and reprioritize a parent with nested substeps; its ID, completion
      status and substep relationships remain unchanged.
- [ ] Rename and reprioritize a substep; its `parentId` and parent remain
      unchanged.
- [ ] A reload retains a saved edit in the same browser; JSON export followed
      by import preserves the updated fields and every other document field.
- [ ] Editing works with keyboard and touch on mobile, has clear French labels,
      and retains a sensible focus destination after save or cancel.
- [ ] Pure update logic is tested for valid updates, invalid/no-op updates,
      parent/substep preservation and immutability of unrelated data;
      `npm run check` passes.
- [ ] No schema version increase, localStorage key change, backend, account,
      synchronization, network request or new third-party runtime dependency.

## Implementation constraints

- Prefer a small pure update function in `site/core.js` returning a new
  document or unchanged state on invalid/no-op edits, without mutating the
  original action or the other actions.
- Keep UI changes focused in `site/app.js` and `site/styles.css` as needed.
- Reuse existing `persist()` and `sortedItems()` behavior.
- Maintain `threadstep.document.v1` data shape and current JSON compatibility.
- Do not modify `.github/workflows/`, `AGENTS.md`, OpenCode/OpenSpec execution
  configuration or credentials as part of feature implementation.
- The OpenSpec `plan` phase should define delta scenarios and implementation
  tasks before the separately authorized `apply` phase.

## Out of scope

Editing subject names, adding due dates, drag and drop, manual action ordering
within priority, multi-user features, remote synchronization, bulk editing,
and new kinds of nested substeps.

## Assumptions and decisions

- This task covers both top-level next actions and existing one-level substeps.
- The chosen UI is a compact inline editor; exact layout may adapt to mobile.
- `done` remains independent of editing and is never reset.
- Creating this specification is **not authorization** to call OpenRouter or to
  run either paid OpenSpec phase, modify app code or merge a pull request.
