## Valeur et décision propriétaire (16 octobre 2026)

Préparer une version de l'orchestrateur à plafond numérique paramétrable de 1 à 10 démarrages de tâches par vague. Conserver une tâche payante à la fois ; préparer une extension ultérieure à 15, non autorisée par ce lot. La documentation des workflows avance en parallèle. Une interruption ou un état incertain ne se répare pas par relance automatique : diagnostic puis autorisation explicite de reprise.

`max_tasks` désigne les réservations/démarrages payants maximaux, jamais dix livraisons garanties ni une limite de dollars.

## Périmètre de CETTE PR, documentaire seulement

- Formaliser les décisions et variantes de conception dans [l'architecture V3](../asf-v3-architecture.md).
- Définir le cycle durable de vague, les invariants de quotas et d'idempotence, l'identité d'autorisation, les transitions de journal, les frontières de permissions et les points de reprise.
- Décrire les impacts de `backlog-orchestrator.yml`, `agent-openspec.yml`, `scripts/asf/waves/*` et leurs tests, sans changer ces fichiers.
- Formaliser une séquence de PR indépendantes pour le contrôleur, l'authentification, les workflows, le budget et les essais.
- Distinguer les choix approuvés par le propriétaire des arbitrages encore à instruire, notamment budgets, dispatch entre runs et politique de durée.

## Critères d'acceptation de ce cadrage

- [x] Choix conservés : première cible 1..10, saisie numérique validée, concurrence 1, documentation en parallèle et reprise manuellement autorisée après diagnostic.
- [x] V1 1/2 inchangée ; schéma de migration versionnée explicité sans migrer l'historique.
- [x] Tous les obstacles techniques connus sont identifiés : YAML à deux slots, readInputs, manifeste, vérification d'autorisation, journal, preuves GitHub.
- [x] Matrice de scénarios positifs/négatifs, tests de frontière 0/1/2/3/5/10/11 et contrôle d'un onzième départ inclus.
- [x] Critères d'arrêt et d'idempotence définis, sans assimiler succès de job à livraison.
- [x] Documentation de conception livrée dans cette même PR.

## Hors périmètre et autorisations

Pas de modification de workflow, code, secrets, GitHub App, protections, budget, PR de code, autorisation de run OpenRouter, lancement de vague, ni fusion. Les tâches ASF sont manuelles et ne deviennent jamais éligibles au scheduler produit. Le présent statut « proposed » n'autorise pas l'Agent ASF V2 à exécuter cette fiche.

## Validation et revue post-PR

Diff documentaire uniquement ; contrôler les liens et l'absence de secrets. Exécuter `npm run check` si l'environnement est disponible, puis vérifier le `check` indépendant sur le SHA final de la PR. Ces validations ne sont **pas** revendiquées comme exécutées dans la fiche. Toute fusion demande une autorisation distincte.
