# TS-039 | Certifier les parcours local-first et Cloud en E2E

## User value
Disposer d'une recette reproductible qui prouve la durabilité locale, la synchronisation multi-appareils et la non-perte de données au-delà des tests Node simulés.

## Scope
- Mettre en place une matrice de validation déterministe pour chaque domaine OpenSpec et un protocole manuel de recette sur instance Dexie Cloud isolée.
- Tester les parcours local-only, activation, première sync, base peuplée, divergence, conflits concurrents, reimport JSON, restauration, déconnexion, changement URL/session et erreurs réseau.
- Rendre visibles les résultats des tests et les limites non prouvées ; documenter la récupération de l'ancien V1 et la non-présence de secrets.

## Acceptance criteria
- [ ] La CI comprend des tests de non-régression automatisables pour les états, la persistance, les empreintes, la sécurité et l'idempotence ; `npm run check` passe.
- [ ] Le protocole manuel explicite Chrome mobile, deux navigateurs, session OTP réelle, offline, réseau intermittent et propagation dans les deux sens ; aucun test non exécuté n'est marqué accepté.
- [ ] Les rapports distinguent preuves CI, recette Dexie réelle, limites et incidents ouverts ; données de test uniquement.

## Implementation constraints
- Ne pas mener de manipulation destructive dans les bases personnelles.
- Les recettes manuelles et vérifications GitHub post-sync ne figurent pas comme cases de checklist `apply`.
- Documenter les divergences entre comportements natifs Dexie et simulations sans les masquer.
- Réviser dans la PR de code les anciennes spécifications OpenSpec contradictoires au périmètre, en appliquant les deltas normatifs et sans effacer leur historique archivé.
- Références cibles : `openspec/specs/local-indexeddb-persistence/spec.md`, `openspec/specs/cloud-sync-lifecycle/spec.md`, `openspec/specs/cloud-opt-in-activation/spec.md`, `openspec/specs/data-backup-import-restore/spec.md`, `openspec/specs/data-reconciliation/spec.md`, `openspec/specs/workspace-identity-isolation/spec.md`, `openspec/specs/threadstep-integration-profile/spec.md`.
- Checklist `apply` limitée aux modifications et tests prouvables sur runner, avec Manual acceptance et Post-sync review hors cases.

## Manual acceptance
Exécuter sur instance Dexie de test l'ensemble de la matrice, vérifier UI tactile/clavier, captures de statuts sans données sensibles, récupération via exports et conservation des relations après réimport. Recette hors runner, non validée par la CI seule.

## Post-sync review
Relire les deltas OPSX, l'archive et l'exactitude du contrat canonique ; vérifier CI indépendante sur le SHA de la PR puis merge, CI de `main` et Pages. Conserver les résultats de recette manuelle distincts.

## Out of scope
Déclenchement automatique d'un coût de service, certification d'un environnement distant non testé, garantie totale de disponibilité Cloud.

## Assumptions or decisions
Architecture local-first et Cloud facultatif approuvée le 18/10/2026 ; tout transfert vers Dexie Cloud exige un opt-in distinct de l'OTP. Le plan OpenSpec résout les choix techniques sous contrainte de sécurité et d'isolation. Aucun modèle payant ne doit être lancé par ce brief.
