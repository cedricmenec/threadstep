## Functional requirements
- FR-01 Create and remove named subject groups.
- FR-02 Add, complete and remove short next-action items in each subject. Removal is immediate and persisted, and offers a non-modal 10-second undo snackbar (« Étape retirée » / « Annuler ») that restores the removed action and its substeps exactly (ids, titles, priorities, completion flags, parent relations and order); the window is tab-local, invalidated by subject removal, JSON import or another tab's local update, and never survives a reload nor creates a new storage key.
- FR-03 Group one level of nested substeps under a parent action.
- FR-04 Prioritize actions as urgent, normal or later, displayed in that order per level.
- FR-05 See the number of unfinished actions across subjects.
- FR-06 Save automatically on this browser in localStorage.
- FR-07 Export state to JSON and import with schema validation and confirmation before replacement.
- FR-08 Serve as static files via GitHub Pages at a repository subpath.
- FR-09 Reorder subjects one position at a time using accessible up/down controls. Preserve the subject order across reload, JSON export and import.
- FR-10 Edit the title and priority of an existing action or one-level substep with explicit save/cancel, validation, accessible controls and automatic local persistence. Preserve IDs, completion flags, parent relations, document version and JSON import/export.
- FR-11 Temporarily hide completed actions and substeps using an accessible view toggle, keeping completed parents visible when they have unfinished substeps. Never modify stored data or JSON exports through filtering.
- FR-12 Offer a deterministic, view-only « Une étape pour maintenant » suggestion of exactly one unfinished top-level action, prioritizing urgency then subject order then item order, with an accessible way to locate it in the list. Only unfinished top-level actions are eligible: completed actions, substeps and completed parents are excluded, and a clear friendly empty state is shown when none exists. The suggestion is recomputed on each activation, never modifies stored data or JSON, and is not persisted across reload. Substeps as candidates, randomness, AI, timers and automatic completion are out of scope.

- FR-13 Let the user explicitly pin exactly one unfinished top-level action as « Je reprends ici » using an accessible French control on each eligible action. Show a single top-of-interface card with the subject, title and priority plus « Voir dans la liste » and « Ne plus suivre »; restoring the selection locally after reload, revealing it accessibly (including on mobile and when completed actions are hidden), replacing it when another action is pinned, and clearing it explicitly or automatically when the tracked action is completed or removed, when its subject is removed, or when an import no longer contains it. Track the stable subject and action IDs (never title or position), keep TS-007 suggestions independent, leave IDs, priorities, completion flags and ordering untouched, and preserve document JSON compatibility by storing this browser-only preference separately and excluding it from exports.

- FR-14 Explain in accessible French why the deterministic « Une étape pour maintenant » suggestion was selected, using its effective priority (urgent, normal or later) and the existing tie-break order of earlier subject order then earlier action order. The explanation is shown only with a valid suggestion, invents no criterion beyond that order, does not alter selection or stored data, remains distinct from « Je reprends ici », and never invokes AI/network or introduces new persistence.

- FR-15 Let the user rank top-level actions manually inside each priority group using a visible French drag handle (mouse, finger or stylus) or accessible « Monter »/« Descendre » controls that move an action one rank and are disabled at the group boundaries. Reordering stays inside the same subject and priority: a drop on another subject, another priority, a substep, empty space or an invalid target is refused with no document mutation and no storage write; priorities never change, substeps follow their parent, and reordering is suspended while completed steps are hidden with a short French explanation. The chosen order is stored in the existing `subject.items` array with no new field, no document version change and no new storage key, survives reload and JSON export/import, and keeps the deterministic suggestion, the « Je reprends ici » tracking and the removal undo coherent.
- FR-16 Let the user temporarily collapse and expand the visible one-level substeps of a top-level action with an accessible French native button whose label is « Voir 1 sous-tâche » (exactly one visible direct substep) / « Voir N sous-tâches » (N > 1) when collapsed and « Masquer les sous-tâches » when expanded, counting the direct substeps visible under the current filters (mouse, touch, Tab, Enter, Space, ≥ 44 × 44 px touch target, accessible name containing that label and naming the action, exact `aria-expanded`, `aria-controls` linked while the list exists). The control appears only on a top-level action that has at least one substep visible under the current filters, never on substeps or on actions without a visible substep. Collapsing hides only that action's substep list while keeping its title, priority, completion state, own controls and neighbouring actions visible and usable, and expanding restores the substeps in the same order and states. Collapse is independent per parent across subjects and is a transient, tab-local presentation state: it survives ordinary re-renders but starts expanded after a reload, in a new tab and after an import. Activating the control performs no save, no `subject.items` mutation, no new localStorage key, no removal, no reorder and no priority or completion change, and leaves the exported JSON, ids, parent relations and order identical; a collapsed list is truly hidden from assistive technology and exposes no keyboard-reachable child, and while « Masquer les étapes terminées » is active expanding never reveals a hidden substep. It changes none of the existing business rules (pending counter, deterministic suggestion, « Je reprends ici » tracking, sorting, editing, completion, reorder, removal, undo), and user titles in accessible names are rendered as text, never as HTML.
- FR-17 Let the user rank the one-level substeps of one parent action manually inside each priority group using a visible French drag handle (mouse, finger or stylus) or accessible « Monter »/« Descendre » controls that move a substep one rank and are disabled at the group boundaries. A substep reorder stays inside the same parent and the same priority: a drop on another parent, another subject, another priority, a top-level action, empty space or an invalid target is refused with no document mutation and no storage write; priorities, ids, `parentId`, titles, `done` flags and other children never change, no second nesting level is created and no item is re-parented or promoted. The chosen order is stored in the existing `subject.items` array with no new field, no document version change and no new storage key, survives reload and JSON export/import, is suspended while completed steps are hidden with the existing French explanation, is not offered for the substeps of a collapsed parent, and keeps the pending counter, the deterministic suggestion, the « Je reprends ici » tracking, the removal undo and the TS-012/TS-013 collapse control coherent. The top-level TS-011 reordering is unchanged.
- FR-18 Let the user change an action's or one-level substep's priority directly from its Urgent / Normal / Plus tard badge by replacing the decorative badge with an interactive French control of the same appearance, operable by mouse, touch, Tab, Enter and Space with Escape closing without writing, a visible focus state, a ≥ 44 × 44 px touch target and an accessible name naming the item and its current priority. Activating the control offers exactly urgent, normal and later and marks the current value; choosing a different priority applies only to the targeted item, updates its badge and `priority-<value>` class immediately, persists once through the existing automatic localStorage write and re-displays the item in the existing urgent → normal → later groups. Re-selecting the current value, closing without a choice or pressing Escape writes neither the document, nor localStorage, nor the export, and the control starts no drag and triggers no completion toggle, substep collapse, removal or title edit. Ids, titles, `done` flags, `parentId`, subject membership, every other item's fields and the relative order inside each group are preserved, no item is re-parented, and the document keeps the `threadstep.document.v1` shape with no new field, storage key, document version or dependency. The full « Modifier » editor (whose priority setting stays available), the pending counter, the deterministic suggestion, the « Je reprends ici » tracking, the filtered list and the TS-011/TS-014 ordering reflect the new priority with no stale state and are otherwise unaffected, and titles render as text, never as HTML.
- FR-19 Let the user open one subject in a dedicated, roomier detail view from an explicit French « Ouvrir le projet » control on each overview subject card, identified only by the subject's stable `id` through a lightweight relative URL fragment (`#/sujet/<encoded id>`) that needs no new data file, storage key, framework or network request. The detail view shows the subject title, its own unfinished-step count and only its top-level tasks and direct substeps, reusing the existing add / edit / complete / collapse / filter / reorder-within-the-allowed-group / remove / undo functions and their validations, priority, parent, filter and ordering restrictions with the same result as the overview, reading and mutating the same document and ids so the global counter, « Une étape pour maintenant », « Je reprends ici » and the JSON export stay coherent and no second copy of a subject, task or substep exists. A « Retour à la vue d'ensemble » control, browser Back/Forward and reloading a valid detail route restore the correct view, while a malformed route or a subject id absent after import or removed meanwhile shows an accessible French fallback with a return control and creates or modifies nothing; opening, closing and switching views are presentation-only and write no localStorage, change no document and add no new field, id, storage key or persistent preference. The detail view also offers a French « Renommer le projet » control opening an explicit form prefilled with the current name with « Enregistrer » and « Annuler » that trims the name, rejects a blank or whitespace-only name or a trimmed name longer than 100 characters, and changes only the targeted subject's `title` while preserving its `id`, items, every `parentId`, order and priority; cancellation, an invalid name or an unchanged name writes nothing, and a valid rename updates the detail header and the overview card immediately and survives reload and JSON export/import with no new field, storage key or document version change. Access, return, rename and step controls are operable by mouse, touch and keyboard (Tab, Enter, Space) with French accessible names, coherent focus, semantic structure, ≥ 44 × 44 px touch targets and titles rendered as text, never as HTML, and no other project appears in the detail view.

- FR-20 Limit each overview project card to the first five visible top-level actions after the existing priority/manual sort and « Masquer les étapes terminées » filter, counting a parent and its direct substeps as one entry and never letting substeps consume a slot. Show exactly one accessible French « Voir plus » control, naming the project, only when more than five top-level actions remain visible; it opens the existing `#/sujet/<id>` detail route with the existing history, return and focus, where no five-task limit applies. Tasks beyond the preview are absent from the overview DOM and are neither keyboard reachable nor drag sources or targets there. Locating a tracked or suggested action that is beyond the preview opens its subject's detail view and reveals it there rather than targeting an absent element. The preview is presentation-only: no change to ids, priorities, completion flags, ordering, counters, JSON export, `threadstep.document.v1` or localStorage, and no new field, storage key or dependency.

- FR-21 Show, in each overview project card header and in the detail view header, an accessible French label giving the subject's total number of top-level tasks (`parentId: null`), including completed tasks and excluding direct substeps, with the accurate agreement « 0 tâche au total » / « 1 tâche au total » / « N tâches au total » (N > 1). The total is computed from the complete `subject.items` on every render and stays independent of the « Masquer les étapes terminées » filter, the substep collapse state and the TS-017 five-entry preview; it updates after an add, a removal, an undo, an import and a reorder. The existing « N étape(s) en attente » counter keeps its exact computation (every unfinished item, substeps included) and wording, is shown as a separate label and is never replaced, renamed or re-scoped. The change is presentation-only: no new document field, id, storage key, preference, migration, network call or dependency, and the label is rendered as a text node perceptible without relying on colour alone.
- FR-22 Let a top-level action or one-level substep carry an optional free-text `note` (Unicode string, at most 2 000 JavaScript characters) entered in the existing inline editor through a labelled multiline « Note (facultative) » control prefilled with the current value. « Enregistrer » validates title, priority and note together: a note longer than 2 000 characters shows an accessible error and saves nothing, a blank or whitespace-only note removes the `note` field, and a non-blank note is stored verbatim with its line breaks. `id`, `done`, `parentId`, subject membership and order are preserved, cancelling or re-saving unchanged values writes nothing, and display shows a non-empty note in the task body as a plain text node with `white-space: pre-wrap` (never `innerHTML`, Markdown, HTML or active links) identically in the overview and the detail view. The note survives completion, priority change, reordering, substep collapse and removal undo, and the JSON export/import preserves it and its line breaks; import validates a present `note` (string, at most 2 000 characters) and rejects an invalid one atomically with a message and no local-data overwrite, while every valid V1 document without `note` stays importable. No new document version, storage key, field on items without a note, migration, dependency or network call is introduced.

## Acceptance tests
- Data survives a reload in the same browser when localStorage is available.
- Text input is rendered safely without HTML interpretation.
- Import rejects unknown format version, invalid priorities, orphan substeps and duplicates.
- Removing an action or substep persists immediately and shows a snackbar « Étape retirée » with « Annuler »; undoing within ten seconds restores the exact action and its substeps and re-persists, while expiry, reload, subject removal, import or an external localStorage update prevent any stale restoration and no new storage key is created.
- Mobile viewport is supported.
- The « Une étape pour maintenant » suggestion is deterministic, excludes completed actions and substeps, and never changes localStorage, exported JSON, ids, flags, priorities or ordering; no card is restored after reload.
- The « Je reprends ici » tracking pins exactly one unfinished top-level action, survives reload, reveals it accessibly, clears on « Ne plus suivre », and is automatically cleaned up when the action is completed or removed or its subject is removed; it uses a browser-local preference separate from `threadstep.document.v1`, is excluded from JSON exports, and never changes ids, priorities, completion flags or ordering.
- No key, secret or personal task content is sent to a server.

- The « Une étape pour maintenant » explanation names the suggested action's effective priority (urgent/normal/later) in French, states the existing tie-break order of earlier subjects then earlier actions without inventing other criteria, and is shown only with a valid suggestion; activating the suggestion, reading the explanation and using « Voir dans la liste » leave localStorage, exported JSON and the « Je reprends ici » tracking unchanged.

- Top-level actions can be reordered within their priority group by dragging the handle or using « Monter »/« Descendre »; cross-subject, cross-priority, substep and empty-space drops change nothing and write no storage; the order survives reload, export and import while ids, priorities, completion flags, parents and the document version stay unchanged; while « Masquer les étapes terminées » is active no handle is shown and the move controls are disabled with a French explanation.

- A top-level action with at least one substep visible under the current filters shows an accessible French native button whose label is « Voir 1 sous-tâche » for exactly one visible direct substep, « Voir N sous-tâches » for N (N > 1) visible direct substeps while collapsed, and « Masquer les sous-tâches » while expanded, its accessible name containing that label and the parent action's title (≥ 44 × 44 px, exact `aria-expanded`, `aria-controls` while the list exists) and no control appears on substeps or on actions without a visible substep; the count follows the « Masquer les étapes terminées » filter and refreshes on the next render after a substep is added, removed, restored, completed or filtered; collapsing hides only that parent's substeps while its title, priority, state and controls stay usable; each parent collapses independently across subjects; expanding never reveals a substep hidden by « Masquer les étapes terminées »; the transient tab-local state survives ordinary re-renders but starts expanded after reload, a new tab and an import; and collapsing writes no localStorage key and leaves the exported JSON, ids, priorities, completion flags, parent relations and order unchanged.

- One-level substeps of the same parent and same priority can be reordered by dragging the handle or using « Monter »/« Descendre »; cross-parent, cross-subject, cross-priority, top-level-action and empty-space drops change nothing and write no storage; the accessible names name the substep, its priority and its parent and the controls are disabled at the group boundaries; the order survives reload, export and import while ids, priorities, completion flags, parents, titles and the document version stay unchanged; while « Masquer les étapes terminées » is active no substep handle is shown and the move controls are disabled, and a collapsed parent exposes no substep handle or drop target; the pending counter, the deterministic suggestion and the « Je reprends ici » tracking are unaffected, and the top-level TS-011 reordering still works.

- The Urgent / Normal / Plus tard badge of a top-level action and of a one-level substep is an interactive control with an accessible name naming the item and its current priority (≥ 44 × 44 px, visible focus, reduced-motion-safe); choosing a different priority applies to that item only, updates the badge and its `priority-<value>` class immediately, re-groups it in urgent → normal → later order and persists through the existing `threadstep.document.v1` write so it survives reload and JSON export/import; re-selecting the current value, closing without a choice and Escape write no document, storage or export; the control starts no drag and changes no completion, collapse, removal, title, id, `parentId` or other item; and the full « Modifier » editor, the counter, the suggestion, the tracking and the ordering keep working.

- The overview « Ouvrir le projet » control of subject A opens a distinct, roomier detail view showing A's title, its own unfinished count and its tasks and direct substeps, and not the B/C cards; every task operation in the detail view (add, edit, complete, filter, collapse/expand, reorder within the allowed group, remove, undo) produces the same document as the overview, and a hidden substep exposes no handle or drop target; a « Retour à la vue d'ensemble » control, browser Back/Forward and reloading a valid detail route restore the correct view, while a malformed route or a subject id absent after import or removed meanwhile shows an accessible fallback without creating or modifying any subject; opening and closing the detail view without a business action leaves the document, localStorage and the exported JSON strictly unchanged with no new field, id, storage key or persistent preference; and renaming A with a valid name updates the detail title and the overview card immediately, survives reload and JSON export/import with no migration, and preserves its id, tasks, parent relations, priorities, completion states and order, while cancelling, submitting a blank or too-long name, or saving the same name writes nothing and a rejected name is announced accessibly.

- With 0, 1, 5 and 6 visible top-level actions a card renders 0, 1, 5 and 5 actions, substeps never consume a slot, the completion filter is applied before the limit and subjects are limited independently; « Voir plus » appears only beyond five, names the project and opens that project's detail view where every filtered action is available, including those beyond the preview; overview actions beyond the quota are absent from the DOM, not focusable and neither drag sources nor targets; the tracking and suggestion shortcuts reveal an action beyond the preview by opening the correct detail view; and the preview, route, filter and quota write neither the document, localStorage nor the exported JSON while counters stay complete.

- With 0, 1 and several top-level tasks a project card header shows « 0 tâche au total », « 1 tâche au total » and « N tâches au total » with correct French agreement; direct substeps are excluded and completed top-level tasks are included; the total does not vary with « Masquer les étapes terminées », substep collapse or the TS-017 five-entry preview, and it updates correctly after an add, a removal, an undo, an import and a reorder while the existing « N étape(s) en attente » counter keeps its own computation and wording; the same total appears in the detail header, the label is plain text and perceptible without colour alone, and no new field, id, storage key, migration, network call or dependency is introduced.

- A top-level action and a one-level substep each accept a note of up to 2 000 characters, including accents, line breaks and HTML-looking text, shown as plain text with no HTML execution; adding, changing or clearing the note through the inline editor saves exactly the new text and no other field, and cancelling, an invalid too-long note or an identical save writes nothing; a missing or legacy note leaves the V1 document and the interface unchanged and historic exports without `note` stay importable while a new export/import preserves notes and their line breaks; an import whose `note` is non-textual or longer than 2 000 characters is rejected atomically with a message and without overwriting local data; and notes survive the existing task operations (priority, completion, removal undo, ordering) without creating any substep level or status, with the field correctly named, the label explicit, the error accessible and the rendering readable on mobile and keyboard, verified by the V1 parser, domain and non-regression tests and `npm run check`.

## Open decisions
- Manual ordering within a priority is delivered in FR-15; automatic archiving remains deferred.
- Synchronization between browser devices is explicitly out of scope.
- After first use, gather feedback before elaborating the product.
