# TS-027 | Authentifier uniquement par OTP email natif Dexie Cloud

## Valeur utilisateur

M'authentifier par code envoyé par email et retrouver ma session sécurisée sur ordinateur ou mobile.

## Périmètre fonctionnel

- Intégrer le flux email/OTP natif Dexie Cloud avec requireAuth: true, par GUI native ou userInteraction ; saisie email, envoi, vérification et session, sans fetchTokens custom ni backend applicatif.
- Aucun écran OAuth, mot de passe, fournisseur social, passkey ou login personnalisé, même si Dexie Cloud expose d'autres providers.
- Gérer code invalide/expiré, nouvel envoi, session valide réutilisée, première authentification hors ligne impossible, session expirée et messages adaptés.
- Définir et vérifier les permissions native Cloud (owner/realm si nécessaire) : pas d'accès non autorisé d'un utilisateur aux données d'un autre, pas de contournement des refus d'origine/identité/droits. Origine GitHub Pages à autoriser dans le service par procédure opérateur hors build.
- Ne jamais transmettre token, code OTP, clés CLI ou identifiants privilégiés dans DOM diagnostic, logs, documentation ou bundle.

## Critères d'acceptation produit

- OTP invalide/expiré refusé sans purge d'historique ; retenter reste possible.
- Session valide restaurée sans nouveau code inutile ; sans session initiale hors ligne aucun contournement de requireAuth.
- Le seul choix de connexion visible est email + OTP ; test du refus de droits/origine.
- Auth et réplication parlent directement à Dexie Cloud, sans backend ni secret machine client.

## Actions d'implémentation vérifiables avant finalisation

- [ ] Tester flux OTP mocké, erreur/expiration, retour session, première session offline et permissions refusées.

## Recette manuelle (hors checklist d'implémentation)

Vérifier réception et saisie du vrai OTP sur base isolée, mobile et ordinateur, refus et reprise de session.

## Risques, dépendances, décisions et exclusions

- Risque **high**, `status: proposed`, `automation: manual` : pas de sélection automatique ni autorisation de coût/fusion implicite.
- Dépendances : TS-024.
- Décision : Ne pas configurer d'autres fournisseurs natifs éventuellement proposés par le service.
- Hors périmètre : OAuth, mot de passe, passkeys, social, backend de jetons ou gestion d'équipe avancée.
- Norme : [spec Dexie Cloud](../../docs/product/specs/dexie-cloud-local-first.md) et [plan de livraison](../../docs/product/dexie-cloud-rollout.md).
