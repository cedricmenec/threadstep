# TS-030 | Durcir, tester et documenter la livraison Dexie Cloud

## Valeur utilisateur

Avoir confiance dans la migration et la synchronisation sur plusieurs appareils, y compris lorsqu'un service ou une transaction échoue.

## Périmètre fonctionnel

- Couvrir automatiquement toutes les garanties listées par le dernier Requirement de la spec : absence d'ouverture sans URL, schéma/version/IDs, requireAuth, OTP exclusif, écriture offline, erreurs locales/cloud, switch non destructif, purge sans delete distant et secrets absents du build.
- Recette intégrée push/pull et permissions sur deux appareils avec instance Cloud strictement isolée ; panne réseau, reprise, conflits et changement d'URL.
- Non-régression de toutes les fonctionnalités ThreadStep : projets, tâches, sous-tâches, notes, priorités, ordre, promotion, retrait/undo, suggestion, suivi, routes et import/export JSON V1.
- Audit sécurité du bundle public : CSP la plus restrictive possible, pas de dexie-cloud.key/json, token administratif, credential serveur, URL d'instance imposée, déploiement Pages sous /threadstep/.
- Mettre à jour documentation produit, guide d'utilisation, architecture, recette et récupération après incidents selon comportement livré, en séparant tests Node, OpenSpec, CI distante, Pages et recette humaine.
- Publication atomique ou protégée par compatibilité, pas de déploiement intermédiaire qui occulte le document localStorage historique.

## Critères d'acceptation produit

- Suite automatique prouve les cas couverts et documente les limites des mocks ; npm run check réussi.
- Essais multi-appareils réels avec Cloud de test validés, sans aucun test destructif en production.
- Test de migration V1, A/B/A, purge, OTP et permission refusée, sync offline/reprise.
- Aucun secret/URL forcée dans les ressources publiées et aucun risque de perte induit par une version intermédiaire.

## Actions d'implémentation vérifiables avant finalisation

- [ ] Écrire matrice exigences/tests, tests automatisés et garde de secrets/build.
- [ ] Mettre à jour docs produit et runbook de reprise sur la base des résultats réellement vérifiés.
- [ ] Exécuter npm run check et openspec validate ts-030 --strict --no-interactive après génération des specs.

## Recette manuelle (hors checklist d'implémentation)

Tester sur PC et téléphone : OTP vrai, sync, mode avion, écran compact, clavier/lecteur d'écran, logout/purge sur bases tests ; vérifier CI et Pages séparément.

## Risques, dépendances, décisions et exclusions

- Risque **high**, `status: proposed`, `automation: manual` : pas de sélection automatique ni autorisation de coût/fusion implicite.
- Dépendances : TS-026, TS-029.
- Décision : Pas de fusion intermédiaire d'une persistance incompatible sans garde garantissant migration et disponibilité.
- Hors périmètre : Tests destructifs sur une DB production, backend applicatif, nouveaux providers auth, auto-merge d'un chantier dangereux.
- Norme : [spec Dexie Cloud](../../docs/product/specs/dexie-cloud-local-first.md) et [plan de livraison](../../docs/product/dexie-cloud-rollout.md).
