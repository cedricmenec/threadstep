# TS-024 | Configurer le socle Dexie.js et Dexie Cloud avant l'ouverture

## Valeur utilisateur

Configurer explicitement mon instance Dexie Cloud, puis retrouver sa copie IndexedDB hors réseau après une session valide.

## Périmètre fonctionnel

- Intégrer Dexie.js et dexie-cloud-addon dans l'app statique JS vanilla sous /threadstep/ avec assets buildés reproductibles, sans script CDN tiers à l'exécution.
- Valider localement une URL HTTPS d'instance Dexie Cloud avant toute construction/ouverture de base synchronisée. Stocker l'URL en local non synchronisé ; aucune URL utilisateur imposée par le build. Écran de configuration obligatoire en absence d'URL valide et aucune opération métier dans ce cas.
- Schéma Dexie explicitement versionné, tables synchronisées à IDs uniques compatibles Dexie Cloud (jamais ++id), versions/upgrades sans suppression implicite ; nom de base stable et nameSuffix natif préservé.
- Appeler db.cloud.configure({ databaseUrl, requireAuth: true }) avant tout accès déclenchant l'ouverture. La validation syntaxique ne dépend pas du réseau ; URL inaccessible = erreur signalée, sans perte de configuration ni bases existantes.
- Adapter strictement la CSP actuelle connect-src 'none' pour les seuls hôtes HTTPS/WSS Dexie Cloud autorisés, en gardant le site compatible Pages. Exclure dexie-cloud.key/json, credentials, token admin et secret du bundle.
- Prérequis non négociable : lever par PR de politique explicitement revue l'incompatibilité de AGENTS.md/vision/MVP actuels (qui interdisent cloud, auth et dépendances JS). Cette tâche n'autorise pas l'agent produit à modifier AGENTS.md.

## Critères d'acceptation produit

- Absence/invalidité d'URL : aucun bootstrap Dexie synchronisé, formulaire accessible, aucune requête métier.
- URL déjà configurée, service inaccessible : base déjà autorisée réouvrable selon conditions native Dexie Cloud, aucune suppression locale.
- Tests de schema/version/ID, nameSuffix, requireAuth, URL purement syntaxique, CSP et chemin Pages.
- Build statique sans URL imposée, clé/JSON Dexie CLI ni autre secret.

Parcours premier lancement et URL déjà configurée, mobile/clavier, hors connexion puis retour réseau et validation de l'origine Pages sur base test.

## Risques, dépendances, décisions et exclusions

- Dépendances : prérequis produit/agent décrits dans le cadrage.

- Hors périmètre : Transactions métier, authentification OTP complète, migration, synchronisation déjà opérationnelle.
