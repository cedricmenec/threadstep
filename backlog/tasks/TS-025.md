# TS-025 | Migrer les opérations métier vers une persistance Dexie local-first

## Valeur utilisateur

Sauvegarder et manipuler les sujets et étapes sans attendre le réseau, avec IndexedDB comme source de vérité.

## Périmètre fonctionnel

- Remplacer le chemin métier localStorage par un adaptateur Dexie asynchrone transactionnel. Conserver site/core.js pur et toutes les règles UI actuelles.
- Modéliser des entités synchronisables sujet/étape assez fines pour éviter l'écrasement d'un document entier quand deux appareils modifient des items distincts. Préserver IDs logiques, parentId, ordres, notes, priorité, done et export/import JSON V1.
- Couvrir création/édition, complétion, sous-tâches, promotion, tri, retrait et annulation, import JSON atomique, filtres, compteur, suggestion, suivi et routes ; préférences strictement locales non synchronisées.
- Observer les écritures multi-onglets sans dépendre seulement de l'événement storage. Validation immédiate de l'enregistrement quand la transaction locale Dexie réussit, sans ACK Cloud ; erreurs IndexedDB différentes des erreurs réseau.
- Aucun déploiement intermédiaire qui masquerait le document existant avant migration TS-026 et OTP TS-027 : garde de compatibilité ou livraison atomique.

## Critères d'acceptation produit

- Toute mutation métier conserve les invariants de contenu et de hiérarchie, y compris export/import JSON V1.
- Hors ligne après initialisation/session, une écriture locale validée est confirmée sans ACK réseau ; un échec IndexedDB n'est pas un succès.
- Deux onglets reçoivent un état cohérent ; mises à jour indépendantes ne s'écrasent pas via whole-document put.
- Aucune donnée historique invisible ou effacée à une étape transitoire.

## Actions d'implémentation vérifiables avant finalisation

- [ ] Construire adaptateur Dexie, projection de document et CRUD transactionnel.
- [ ] Tester hors ligne, transaction échouée, deux onglets, conflits, JSON V1, notes, ordre, promotion, undo, suivi.
- [ ] Exécuter npm run check et openspec validate ts-025 --strict --no-interactive.

## Recette manuelle (hors checklist d'implémentation)

Manipulations en navigateur et mobile après session, coupure réseau, import/export, navigation et filtres.

## Risques, dépendances, décisions et exclusions

- Risque **high**, `status: proposed`, `automation: manual` : pas de sélection automatique ni autorisation de coût/fusion implicite.
- Dépendances : TS-024.
- Décision : Ne pas considérer la synchronisation réseau comme condition de réussite d'une écriture locale.
- Hors périmètre : Conversion de la clé localStorage V1 (TS-026), flux OTP (TS-027), indicateur global (TS-028).
- Norme : [spec Dexie Cloud](../../docs/product/specs/dexie-cloud-local-first.md) et [plan de livraison](../../docs/product/dexie-cloud-rollout.md).
