## Objectif

Fournir des projections compactes, reproductibles et validées en CI à partir des seules tâches Markdown.

## Références normatives

- [../specs/backlog-v2.md ](../specs/backlog-v2.md)

## Périmètre

- Implémenter un parseur YAML strict : champs obligatoires, doublons de clés, types, énumérations, IDs et chemins sûrs.
- Valider les identifiants uniques sur tâches actives et archivées, dépendances connues, doublons, auto-références et cycles.
- Produire backlog/index.json et backlog/archive-index.json, tri stable et SHA-256 des octets du fichier, sans inclure le corps Markdown.
- Ajouter des commandes generate/check et intégrer check à npm run check, sans écriture en mode check.

## Critères d'acceptation et vérification

- [ ] 100 tâches fictives génèrent le même index à contenu égal sans LLM ni réseau.
- [ ] Une clé dupliquée, un cycle, un ID double et un index obsolète échouent avec un diagnostic.
- [ ] Une référence à une archive valide reste possible ; la présence en archive ne prouve jamais delivered.
- [ ] Tests déterministes et npm run check passent.

## Contrat d'exécution

- **Périmètre de fichiers envisagé :** scripts/asf/ ; tests/ ; backlog/index.json ; backlog/archive-index.json ; package.json ; docs/factory/.
- **Hors périmètre :** Pas de livraison GitHub vérifiée, ni déplacement historique ni appels payants.
- Implémenter sur branche dédiée depuis main, avec une PR d'implémentation **indépendante** après livraison réelle des dépendances.
- Cette tâche concerne la factory. Le workflow OpenSpec actuel n'accepte que TS-NNN et refuse des chemins internes protégés. Utiliser une voie d'implémentation ASF spécifiquement autorisée, sans contourner les contrôles des agents produit.
- Dans la même PR, documenter les changements effectifs sous docs/factory/ et mettre à jour la checklist de cette tâche uniquement pour les tests réellement effectués. Exécuter `npm run check` et, si GitHub Actions est modifié, Actionlint et la vérification Bash.
- La création et la fusion documentaire de cette tâche **n'autorisent pas** l'exécution payante, la fusion de la PR d'implémentation, la modification de secrets ou de permissions.
