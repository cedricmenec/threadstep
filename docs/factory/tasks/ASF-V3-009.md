# ASF-V3-009 | Préflight du mandat propriétaire avant tout émetteur V3

Status: proposed implementation, draft PR; NOT connected to workflows
Automation: manual
Type: factory
Priority: high
Created: 2026-10-17
Dependency: ASF-V3-008 (#77), itself based on ASF-V3-007 (#75)

## Valeur fonctionnelle

Rendre impossible qu'un **simple run GitHub avec le bon acteur et le bon SHA** soit interprété comme un mandat propriétaire de lancer jusqu'à 10 tâches. Vérifier séparément les valeurs explicitement choisies au départ par le propriétaire, les éléments du manifeste V3 figé et les métadonnées **rechargées** du run GitHub. Ne jamais transformer le succès de ce préflight en autorisation de signer, dispatcher, exécuter le modèle ou fusionner.

## Contrats critiques

**Le runtime produit les inputs.** Les données \`ownerContext\` ne peuvent pas provenir d'un appel API utilisateur, d'une PR, d'un manifest, d'une branche de vague, de l'Agent ou d'une chaîne JSON du modèle. Elles doivent provenir directement du contexte d'événement \`github.event.inputs\` d'un workflow owner-dispatched **protégé et approuvé**. Le module présent ne peut pas certifier cette origine : il fait seulement une comparaison.

**Le run GitHub est observé, pas considéré comme source des inputs.** \`GET /actions/runs/{run_id}\` peut établir l'acteur, le runId, la branche, le path de workflow, le SHA et la tentative. Il ne remplace pas le contexte d'événement authentique pour établir les valeurs choisies au dispatch.

**Mandat = valeur explicite, pas liste de tâches devinée.** Le \`candidate_set_sha256\` est un hash canonique de la **liste ordonnée** des candidats \`[{id, sha256}]\`. Toute différence de contenu ou d'ordre entraîne le refus. Ce hash doit être calculé sur un ensemble figé par un composant fiable avant ou au moment de l'expression de la volonté owner ; aucun composant ne peut créer arbitrairement le mandat après signature.

Le prochain issuer n'a **aucun** secret, token, private key ou droit de signer disponible dans cette PR. Ne pas ajouter de routine de signature ou d'App write sans approbation owner distincte. Même un check vert ne supprime pas le P0 issuer/pinning de #77.
