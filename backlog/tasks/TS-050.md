# TS-050 | Conserver l'ouverture des sous-tâches pendant les rafraîchissements

## User value

Une tâche parente développée ne doit pas se replier lorsque je coche une sous-tâche ni lorsqu'une synchronisation arrive en arrière-plan. Mes choix d'affichage restent valables tant que je travaille dans la même vue.

## Constat vérifiable

La spécification canonique `openspec/specs/substep-collapse/spec.md` impose déjà de conserver l'ouverture pendant les simples re-renders de la vue. Dans `site/app.js`, `load()` réinitialise pourtant `expandedParents`, et le `syncComplete` Dexie Cloud ainsi que le canal `BroadcastChannel` invoquent `load()`. Un rafraîchissement de données peut donc réinitialiser le repli sans véritable navigation. L'observation utilisateur exacte reste à confirmer sur mobile/Cloud de test.

## Scope

- Distinguer l'initialisation d'une session/vue des rafraîchissements métier et événements asynchrones.
- Conserver `expandedParents` pour les parents encore existants lorsque les données de la vue courante sont actualisées après coche, édition, changement de priorité, réordonnancement, ajout, réception inter-onglet ou fin de synchronisation Cloud.
- Réinitialiser l'ouverture uniquement pour les événements explicitement prévus par la spec : chargement réel/rechargement, nouvel onglet, import réussi et nouvelle entrée dans une vue par navigation.
- Conserver les règles du filtre des éléments terminés : ne pas faire réapparaître des sous-tâches filtrées ; un parent sans enfant visible peut perdre sa commande.
- Respecter l'isolation des données et les changements d'identité Cloud : un espace non autorisé ne doit jamais rester visible par conservation d'état.
- Préserver l'accès clavier, `aria-expanded`, le focus et les comportements de révélation volontaire.

## Acceptance criteria

- [ ] Cocher ou décocher une sous-tâche dans un groupe ouvert conserve son ouverture et celle des autres groupes visibles dans la même vue.
- [ ] Une modification locale ou un rafraîchissement Dexie Cloud sous la même identité autorisée n'est pas traité comme une entrée de vue.
- [ ] Une notification inter-onglet conserve l'ouverture des parents toujours visibles sans écriture de préférences de repli.
- [ ] Une navigation vers une nouvelle vue, un vrai rechargement, un nouvel onglet ou un import réussi réapplique l'état initial replié conforme à TS-021.
- [ ] Les changements de filtre, suppression du dernier enfant et changement de compte ne compromettent ni l'accessibilité ni l'isolation des données.
- [ ] Les tests de régression ciblent distinctement `load()`, `syncComplete`, `BroadcastChannel`, `hashchange` et l'import ; `npm run check` passe.

## Implementation and testing guidance

- Refactorer la frontière `load()` pour séparer `refresh data` et `reset transient view state` ; éviter toute réinitialisation de `expandedParents` sur les simples rafraîchissements.
- Mettre à jour les tests existants `tests/substep-collapse-default.test.mjs` et `tests/task-actions-menu.test.mjs`, dont certains supposent actuellement à tort que chaque appel de `load()` doit replier les sous-tâches.
- Tester sans falsifier les événements natifs Dexie ou ignorer les échecs de lecture et les barrières de liaison.
- Vérifier la cohérence avec `openspec/specs/substep-collapse/spec.md` et le contrat transversal UX s'il est disponible.

## Manual acceptance

Tester sur deux navigateurs/onglets et Chrome Android avec une base Dexie Cloud de test, notamment hors ligne, retour réseau, notification `syncComplete`, coche, filtre et changement de vue. Confirmer que seuls les événements de véritable nouvelle entrée réinitialisent les groupes ; contrôler clavier et lecteur d'écran. Une CI verte ne remplace pas cette recette.

## Implementation constraints

- Coordination obligatoire avec TS-048 et TS-045 sur les chargements asynchrones et la liaison de compte ; éviter une implémentation parallèle conflictuelle sur `site/app.js`.
- Ne jamais relâcher le contrôle d'identité, masquer une erreur Cloud, écraser des données, supprimer un cache ou déduire la convergence de `in-sync`.
- Aucune modification de schéma, d'export, ni persistance supplémentaire de `expandedParents`.

## Out of scope

Mémorisation de l'expansion entre visites, changement du comportement initial replié, nouvelle profondeur de sous-tâches, refonte de la synchronisation ou réparation de TS-048.

## Assumptions or decisions

Le risque est `medium` car la correction touche les événements de chargement Cloud. `automation: manual` impose une revue avant exécution ; aucune dépense ni fusion implicite.
